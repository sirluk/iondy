In this article I would like to give a short introduction for an elegant technique to make finetuning of large language models more storage efficient. From my own experience it is often the case that one has several instances of BERT stored on disk which only differ in terms of how much the weights were changed during task-adaptation. Diff-Pruning, which was developed by Guo et. al. in 2021 is a training technique which aims at tackling this problem. The basic idea of Diff-Pruning is to limit the amount of weights which are adapted during finetuning of a pre-trained model and to only store the difference of weights compared to their pre-trained state. The loss in performance compared to full finetuning was shown to be very minimal even with only .5% of the parameters of a full BERT_large model.

I came across Diff Pruning when I was looking at different sparsification techniques for a research project I am involved in. Unfortunately the code from the authors was set up in a way that it was difficult for me to integrate and expand which is why I decided to create my own Pytorch implementation from scratch. After a quick conceptual overview of the ideas presented in the paper, I will use my re-implementation in this article to explain how Diff-Pruning works in practice. The code from the original paper can be found on github.

What is Diff-Pruning

As already mentioned Diff-Pruning tries reduce the number of weights that get changed during finetuning of a pre-trained language model like BERT. It is important to note that it does not try to reduce or change the pre-trained model weights in any way. For this reason, a first important step for Diff-Pruning is to not think of just the set of model weights θ_pre that get changed during finetuning to task-specific θ_τ but to think of separate fixed pre-trained weight values θ_pre and task-specific “diff”-values δ_τ.

The initial state of all weights in δ_τ is 0. We now want to limit the number of δ_τ,i which change to non-zero value during training. This constraint can be expressed as a L0 penalty in the loss function.

For the set of parameters δ_τ the term 1{δ_τ,i≠0} equals 1 if δ_τ,i is non-zero. L is some Loss function, d represents the total number of parameters in the model and λ is a hyperparameter to control the degree of regularization. Since this penalty term is not differentiable however, it poses a challenge for training using gradient techniques. Thankfully there is a solution to this problem which was initially proposed by Louizos et. al. in 2018. They approximate the L0 objective via stochastic gates to make it differentiable. Stochastic gates in neural networks make use of the reparameterization trick (Kingma and Welling, 2014). Explaining the details about how it works would go beyond the scope of this article but there is a great many resources only which do just that, for example this one.

Magnitude Pruning

In principle with these building blocks Diff-Pruning can be integrated into a typically Pytorch model pipeline. However there is one step left in Diff-Pruning which I haven’t mentioned so far. With the training procedure outlined above it is not really possible to control the exact degree of sparsity in the δ values. This is why Guo et. al. apply magnitude pruning to the diff values after training for some epochs. In magnitude pruning you define an exact sparsity percentage, lets say 5%, and then keep only the top 5% of weights in terms of their magnitude.

For Diff-Pruning if you want the parameter count down to 5% or even lower, it is quite a big reduction from the first stage where the z-masks are trained (this resulted in around 20%-30% of parameters being zeroed out in my experiments). This is why it is important to keep training the model after the magnitude pruning step for some epochs. For this to work in my implementation I needed to create a new parameterization for this training procedure after magnitude pruning as now the z-masks are fixed and we just need to prune the remaining δ values.

Final thoughts

You can find my code on github and some experiments I did on tensorboard. The code is a bit more extensive than what is shown in the article as I also implemented structured Diff-Pruning for example but I am happy to answer questions about it in the comment section. The tensorboard includes runs for two datasets GLUE-SST2 and a custom dataset where a job category needs to be predicted based on short biographies. Furthermore, I tested three different model versions:

  • diff_pruning_fixmask: the regular (+structured) Diff-Pruning training procuedure I outlined in this article
  • finetuning_fixmask: regular finetuning but with magnitude pruning after some epochs. This experiment shows that diff_pruning is important as with magnitude pruning only here we do not recover much of the accuracy.
  • finteuning_no_fixmask: this is just regular finetuning as a reference baseline.

I hope with this article I was able to give you some insights into how Diff-Pruning works and how it can be implemented in Pytorch. Even though there have been new techniques with even better performance like FISH Mask (Sung et. al., 2021) I think Diff-Pruning has some potential for further research as an elegant way to sparsify large models.
